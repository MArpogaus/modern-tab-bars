** About The Project

A starting point for an Emacs Lisp package that is ready for MELPA on
day one: the file headers, the checks and the CI workflow are already
in place, so the first commit is about the feature and not about
scaffolding.

Everything here is checked by the same pipeline the other packages use.
Running =make= byte-compiles with warnings as errors, runs =checkdoc=
and =package-lint=, and runs the test suite.

** Getting Started

*** Use the Template

Create a repository from this template on GitHub, then rename the
placeholder to the package name.  The name appears in the file names,
in the symbol prefix and in the URLs:

#+begin_src shell
  name=your-package
  git mv modern-tab.el "$name.el"
  git mv test/modern-tab-test.el "test/$name-test.el"
  grep -rl modern-tab . --exclude-dir=.git | xargs sed -i "s/modern-tab/$name/g"
  grep -rl modern-tab-bars . --exclude-dir=.git | \
      xargs sed -i "s/modern-tab-bars/$name/g"
  make
#+end_src

Then write the feature, adjust =Package-Requires= to the oldest Emacs
release you support, and list that release first in the CI matrix.

** Development

*** Make Targets

| Target     | What it does                                    |
|------------+-------------------------------------------------|
| =compile=  | byte-compile, warnings are errors               |
| =checkdoc= | documentation style, any output fails           |
| =lint=     | package-lint, the rules MELPA applies           |
| =test=     | ERT suite                                       |
| =clean=    | remove build output and the tool sandbox        |

Plain =make= runs all checks in that order, exactly as the CI does.
The =lint= target installs package-lint into =.sandbox/=, so a fresh
checkout needs nothing but Emacs and =make=.

*** Conventions

- One package prefix for every symbol; private ones use a double dash.
- Every file carries the header block, =;;; Commentary:=, =;;; Code:=,
  a =provide= form and the footer comment.
- Autoload cookies on the entry points only: commands, minor modes and
  variables a user sets before the package is loaded.
- Docstrings end sentences with two spaces, name their arguments in
  upper case and quote symbols as =`symbol'=.
- Commits follow the conventional commit style; work happens on =dev=
  and reaches =main= as a merge commit, which is then tagged.
- Code written with an AI assistant carries an =Assisted-by:= line under
  the =Author:= line, which is what MELPA asks for:
  =;; Assisted-by: Claude:claude-opus-5=.

** Publishing on MELPA

1. Tag a release, so MELPA Stable has something to build.
2. Fork [[https://github.com/melpa/melpa][melpa/melpa]] and add =recipes/<package>=:

   #+begin_src emacs-lisp
     (modern-tab
      :fetcher github
      :repo "MArpogaus/modern-tab")
   #+end_src

   Add =:branch "main"= when the default branch is not the one to
   package.  The =.elpaignore= file keeps the tests and the CI files
   out; a =:files= specification is not needed.
3. Check the recipe locally in the melpa checkout:

   #+begin_src shell
     make recipes/modern-tab
     make sandbox INSTALL=modern-tab
   #+end_src
4. Open the pull request.  The checklist in the template asks for the
   package to be lint-clean, which =make lint= already answers.
