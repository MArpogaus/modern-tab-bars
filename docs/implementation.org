#+TITLE: How modern-tab-bars is built
#+OPTIONS: toc:nil

Three files.  =modern-tab.el= holds what both modes draw with,
=modern-tab-bar.el= dresses the tab bar and =modern-tab-line.el=
dresses the tab line.  The package prefix is =modern-tab-= for all
three: package-lint takes the prefix from the main file's name, and
both mode names live under it.

* The indicator

The bar beside a tab is a PBM image of one colour, built once per
height, width and colour and kept in a hash table.  Building one means
a fresh payload string and a spec the image cache then compares whole,
and a row of tabs is built again on every command.

A frame without images — a terminal, or one built without PBM — draws
one column of =|= instead.  The face is only put on where a colour was
given: a face attribute of nil is not "leave it alone", it is an error
the display logs on every redisplay.

Each mode names an option per state: a width and a colour for the
selected tab, a width and a colour for the others.  The two modes name
them the same way, so a reader who has set one knows how to set the
other.

* Icons, and what a frame can draw

=modern-tab-glyph= takes candidates and answers with the first the
frame can really draw, the last one being the answer where it can draw
none.  The question is asked with =font-at=, of the string and the face
it carries: a nerd-icons glyph names a font family of its own, and
asking whether the buffer's default font has the character answers for
a font that draws nothing here.  In a buffer where =mixed-pitch-mode=
remaps the default face, that mistake reads every nerd glyph as
missing.

Finding a nerd icon walks the table of its style — 6880 entries for the
material design one — so an answer is kept per key and per display.  A
terminal and a graphic frame answer differently and one session can
hold both, which is why the display is part of the key.  The table is
emptied when a font arrives (=after-setting-font-hook=) and when an
option an icon depends on is set.

* What a mode gives back

Both modes set variables that belong to Emacs, and both put them back:
=custom-reevaluate-setting= gives a variable the value its own
customization says it has, which is the value the reader would have had
without the mode.  The buttons of the tab bar have no public way back,
so the teardown calls =tab-bar--load-buttons=, the function that made
them.

* The tab line hides itself

A row of tabs with a single tab on it says nothing and costs a line of
every window, so a window showing one buffer gets =tab-line-format= of
=none= as a window parameter.  Two hooks keep that current:
=buffer-list-update-hook= for the selected window and
=window-state-change-hook= for every window of the frame.  Turning the
mode off takes the parameter off every window of every frame.

* The tab bar in a terminal

A terminal paints the tab bar row in the redisplay that turns the bar
on.  With =tab-bar-format-menu-bar= in the format, a tab that changes
before that redisplay leaves the row blank for the rest of the session,
and neither =force-mode-line-update= nor =redraw-display= brings it
back.  Measured with Emacs 30.2, in tmux 3.7 and under pyte.  So the
format is filtered on a terminal and the menu button goes; =M-`=
reaches the menu there in any case.

The spacers are the same story.  A =space-width= display property
paints no part of a cell in a terminal, and one such item in the format
leaves the whole row unpainted, still showing what stood in it before.
A terminal gets a plain space instead.

* Complexity

=make complexity= reports the cognitive complexity of every function,
counted the way SonarSource defines it: a branch costs one, a branch
inside a branch costs one plus its depth, a sequence of =and= or =or=
costs one, and a straight line costs nothing.  It is a report and not a
gate — the number says how much a reader has to hold in their head, and
15 is where a function is worth a second look.

The tool is =tools/complexity.el=, shared with the other packages here.
